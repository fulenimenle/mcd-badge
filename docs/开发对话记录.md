# 开发对话记录（腾讯 WorkBuddy）

> 本作品全程在**腾讯 WorkBuddy** 中开发完成。本文档为开发对话的过程记录，供大赛核验「使用 WorkBuddy 开发」之用。
> 记录时间：2026-10-24 12:47 ~ 至今（单次会话内完成）

## 对话时间线

### 1. 需求确认
**用户**：转发腾讯云开发者社区《WorkBuddy 和麦当劳，欢迎你来程序员创意开发大赛》一文，问「这个你看看我可以怎么做，你有什么 idea」。

**WorkBuddy**：检索并汇总了赛事信息（M-China 官方仓库、报名截止 10-25 23:59、按 GitHub Star 排名、前 100 名有实体徽章、用 WorkBuddy 开发另有积分）。分析了榜单在做什么：
- 红海（避雷）：省钱/凑单策略类（榜单前三：mcd-saver-strategist 611★ / mcd-budget-meal 512★ / mcd-coupon-strategist 491★）
- 红海：卡路里/营养计算类（榜单中一批：mcd-calorie-butler、walk-kcal、mcd-order-calories 等）
- 已有：口味测试类「麦门胃」（mcstomach）

提出差异化方案：「**麦门工牌**」——用真实订单数据生成程序员工牌卡片，晒图传播逻辑优于工具类。用户认可并完成 Token 申请。

### 2. 文档调研
**WorkBuddy**：抓取 open.mcd.cn/mcp/doc，确认接入参数（端点 mcp.mcd.cn、Streamable HTTP、Bearer 认证、600 次/分钟限流）与全量工具清单（点餐、订单、优惠券、积分商城、抽奖、活动日历等约 30 个工具）。

### 3. Token 验证
**用户**：提供已激活的 MCP Token。
**WorkBuddy**：编写零依赖 Node 客户端，完成 `initialize` 握手 + `now-time-info` 自检，Token 验证通过（serverInfo: mcd-mcp 1.0.0）。

### 4. 只读数据验证
**WorkBuddy**：调用 `query-my-account`（返回积分 29.8）与 `order-list`（返回最近订单：一笔早餐麦满分套餐 0 元单 + 一笔随心配 13.9 元单，门店信息已匿名化），确认数据结构后设计统计口径。

### 5. 核心开发（WorkBuddy 编写全部代码）
- `scripts/mcp-client.mjs`：零依赖 MCP 客户端模块——JSON-RPC over Streamable HTTP，双格式响应解析（JSON / SSE `data:` 行），`Mcp-Session-Id` 会话管理，协议版本回退（2025-03-26 → 2024-11-05），网络抖动自动重试。
- `scripts/mcd.mjs`：CLI（ping / tools / call）。
- `scripts/collect-stats.mjs`：数据聚合——只读拉取订单+积分，计算职位（规则引擎：0 元单 × 时段分布 × 常点品类映射，如「早八薅羊毛架构师」「咖啡因系统架构师」）、技能栈 chips、KPI、常去据点。
- `scripts/make-badge.mjs`：工牌渲染——纯 SVG 矢量卡片（1120×700，麦门红金配色、金拱门示意、条码、游标式纵向排版），输出 SVG + HTML（浏览器一键存 2x PNG）。附 `--demo` 模式生成虚构数据演示卡。
- 过程中 WorkBuddy 自查发现并修复：① 端点笔误（mcd.mcd.cn → mcp.mcd.cn）导致 fetch failed；② SVG 层叠顺序错误（白卡底误画在头像之后）；③ 年度鉴定框与页脚条 8px 重叠（改游标式布局并收紧节奏）；④ 信息格将「最近打卡」升级为更有信息量的「常去据点」。

### 6. 实测结果
以用户真实数据渲染工牌：职位「早八薅羊毛架构师」、技能栈「咖啡因驱动 / 薯条带宽优化 / 板烧内核 / 汉堡高吞吐 / 气泡缓存」、鉴定语「早八麦门人，原味板烧鸡腿麦满分重度依赖——吞吐稳定，气泡充足，唯一 bug 是 0 元单占比 50%，建议查一下是不是把优惠薅成了个人 KPI。」渲染结果经视觉核对通过。

### 7. 交付物整理
WorkBuddy 编写：SKILL.md（WorkBuddy 技能定义，含执行流程与红线）、README.md（含演示图与快速开始）、CONTEST_DECLARATION.md（参赛声明：原创性/粉丝二创/只读承诺/隐私承诺）、docs/MCP接入说明.md、本开发对话记录，并初始化 git 仓库。

## 开发方式说明

以上全部代码与文档均由腾讯 WorkBuddy 在对话中生成，用户仅做决策确认（选创意、提供 Token、确认方案）。代码仓库零 npm 依赖，Node ≥ 18 可直接运行。
